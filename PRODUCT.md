# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

People using Codex or Claude to start and maintain code, analysis, research, and knowledge-work projects. Assumption pending the optional audience question: readers have basic familiarity with coding agents, but should not need familiarity with harness engineering.

## Product Purpose

Starter gives work a durable home, a short map for agents, and a way to check outcomes. The website explains the concept, offers a minimal starting path, and makes the reasoning and sources readable.

## Positioning

An explicit template, shared scaffold skill, and dependency-free Python generator create a minimal project knowledge structure without imposing an application stack. Website and distribution descriptions are excluded from generated projects.

## Operating Context

The user invokes the scaffold through an agent or CLI, tailors a brief, and works in a repository containing docs, analysis, data, reports, presentations, and outputs. Larger tasks use plans and ownership; completed work leaves evidence and context for another session.

## Capabilities and Constraints

Four scaffold kinds; preserved existing Git metadata; refusal to overwrite nonempty work; structural documentation checks. No guaranteed agent compliance, automatic orchestration, automatic merge, or installed plugin bundle. Existing Next.js/React site remains separate from template/. This build is local; publication is separate.

## Brand Commitments

Name: Starter. By Tom Spencer. Clear, concise, factual writing without sales language. The user permits creative flair distinct from the main personal website and requests Motion Primitives Pro, pared-back shadcn/ui, original diagrams, and the supplied Noir reference.

## Evidence on Hand

Maintained docs, generator and tests, reports/harness-workflow-review.md, reports/website-research.md, the source article and user-supplied PDF, Pro component source, Nim, and user-supplied noir.zip. No testimonials, adoption statistics, productivity benchmarks, or accepted autonomous-run evidence are available.

## Product Principles

- Start with a question and the smallest useful result.
- Make relevant context accessible without requiring all of it up front.
- Keep instructions, executable checks, and observed outcomes distinct.
- Add tools and structure only for a real task.
